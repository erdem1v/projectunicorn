- card names cut with "…" after two lines.

- Brief every UI agent with N4 read strictly: no `…`, no clipping, no hidden overflow.
- Have every UI agent run a sweep for `text_overrun_behavior`, `clip_text`, `max_lines`, `visible_characters` and
  fixed-width cuts.

  on their own.

Runtime-verifying Project Unicorn (Godot 4.6) through the Godot MCP:

**Logic / console checks:** `mcp__godot__editor-run` launches the project **headless** (`--headless -d`) — fine for driving systems + reading `mcp__godot__editor-debug-output` (the `[SalesSystem]/[EventManager]/[VH]` prints), but it has **no rendered viewport, so `capture-screenshot` returns nothing useful**. A throwaway harness scene that drives systems in `_ready()` and prints PASS/FAIL is the reliable pattern; do NOT call `get_tree().quit()` or the process dies before you can read output — leave it alive and `editor-stop` after.

**Screenshots / visual checks:** you must launch a **windowed** instance yourself, NOT via editor-run. Use PowerShell `Start-Process` with the args as a SINGLE quoted string (the project path contains a space — `…\project steam\…` — so a PowerShell array splits it and Godot aborts with "Invalid project path"):
`Start-Process godot.exe -ArgumentList '--path "C:\Users\erdem\Desktop\project steam\project-unicorn" res://scenes/test/<harness>.tscn'`
The runtime addon then prints "Server listening on port 7777" and `capture-screenshot` / `call-runtime-method` / `inspect-runtime-tree` target it.

**Port 7777 is single-instance:** only one game process binds the runtime addon. If another instance (a leftover playtest, or editor-run's headless one) holds it, the MCP runtime tools talk to the WRONG process (you'll see a different scene tree / stale save). Kill strays (`Get-CimInstance Win32_Process -Filter "name like '%godot%'"` → `Stop-Process`) before launching your windowed harness. The runtime tools (groups `runtime` + `testing`) are deferred — load via `tool-catalog`/ToolSearch.

**Reaching game state without onboarding:** a harness scene can `GameState.initialize_run(payload)` then mount `res://scenes/main/GameShell.tscn` and call `ProductSystem.start_build("ai_assistant", ["ai_assistant_chat","ai_assistant_memory"], "")`. Expose `vh_*` methods on the harness root and trigger them via `call-runtime-method` between screenshots. Note `initialize_run` does NOT reset `flags` or `CustomerRegistry`; `product_tab` re-routes only on `day_advanced`/sales signals (not `build_phase_changed`). `--skip-onboarding` / F12 also jump to GameShell (debug builds).

**Runtime bridge input/arg limitations (2026-07-13, verified the hard way):** `call-runtime-method` args CANNOT satisfy typed GDScript params — int/bool/Dictionary all fail (Dictionary throws an explicit "Cannot convert argument 1 from String to Dictionary" at the `callv` boundary; method not run). Only ARGLESS methods are reliable; for parameterized debug paths add an argless relay on a Node (statics unreachable — nodePath required), e.g. `GameShell.debug_force_month_extreme()`. **EXCEPTION — single String args DO marshal:** `call-runtime-method /root/EventBus emit_signal "<signal_name>"` works (returns 0) and fires the signal, so the reliable way to verify a debug HOTKEY whose handler lives in the main loop is to emit its EventBus signal directly rather than inject the key — mandatory for SHIFT-modified or F-key shortcuts (2026-07-14: verified the Shift+F4 onboarding-retrigger this way; `inject-key` both mis-maps F-key names AND silently drops the shift modifier, so it can't reproduce Shift+F4 at all). `inject-key`: key NAMES don't parse ("F5" → keycode 5, "Space" → error) — use NUMERIC keycodes (F1=4194332…F11=4194342, Space=32, Enter=4194309); the `shift` param is NOT honored on the synthesized event (Shift+F11 arrives shiftless). Injected keys reach `_input` handlers (F-keys work) but NOT the GUI focus dispatch (Enter won't activate a focused button). `inject-mouse-click` lands at (0,0) regardless of x/y. Bottom line: drive UI verification via argless runtime methods + screenshots; reserve injected keys for raw `_input` hotkeys only.

**New `class_name` scripts need a cache rebuild before ANY run (2026-07-14):** after creating scripts that declare `class_name X` (or referencing them via preload in an already-loaded script), a headless/MCP run fails with `Parse Error: Identifier "X" not declared in the current scope` / `Could not find type "X"` even though the code is correct — the global class cache (`.godot/global_script_class_cache.cfg`) is stale. Fix: run `--headless --import` once (prints `update_scripts_classes | X`), which registers the new globals; then the run parses clean. The `--import` pass ALSO imports new texture assets (e.g. renamed `.webp`) so runtime `load(path)` resolves. Do it after adding each batch of new `class_name` files, before editor-run.

**Pure-CLI headless smoke (no MCP, fastest for the `endgame_smoke` suite) (2026-07-14):** the console build is at `C:\Users\erdem\Desktop\Godot_v4.6.2-stable_win64_console.exe`. Loop cases from PowerShell capturing stdout via the pipe (`$out = & $exe --headless --path $proj --endgame-smoke=<case>`; then `$out | Select-String "SMOKE (PASS|FAIL)"`). Two gotchas: (1) a NEW `class_name` needs a scan first — `& $exe --headless --path $proj --editor --quit` registers it (prints `update_scripts_classes | X`), same effect as `--import`; without it every case fails `Identifier "X" not declared`. (2) `main.gd`'s smoke path historically `return`ed WITHOUT quitting (the "left ALIVE" note in `endgame_smoke.gd` is for MCP editor-run reading the live log), so a CLI run **hung** and file-redirected stdout never flushed. FIX now in `main.gd`: after `run_case`, `if _smoke_case_on_cmdline(): get_tree().quit()` — quits only when the arg is on the actual command line (CLI), leaves the MCP/`ProjectSettings.main_args` path alive. So CLI runs now self-quit + flush; the pipe capture works.

**No-MCP windowed screenshot (2026-07-14):** run WINDOWED (omit `--headless`) with a debug cmdline flag whose handler calls `get_viewport().get_texture().get_image().save_png("user://x.png")` then `get_tree().quit()`; read the PNG from `C:\Users\erdem\AppData\Roaming\Godot\app_userdata\Project Unicorn\`. === partial-staging-shared-tree
---
name: partial-staging-shared-tree
description: How to commit only your own work when a parallel session is editing the same files, and how to prove the resulting tree is real
metadata:
  type: feedback
---

Erdem 2026-08-21: "stage only my own files — the parallel session's work is not mine to commit."
When the shared files are shared *inside*, whole-file staging cannot honour that. The working
method:

1. Classify every changed file as mine / theirs / mixed by reading the diffs, not by filename.
2. For mixed files, dump `git diff -U1` split at `^@@`, keep only my hunk indices, reassemble
   with the original file header, and `git apply --cached --recount`. Index-only — the working
   tree is never touched, so the other session keeps its edits.
3. **Re-derive the hunk indices immediately before staging.** They shift whenever either session
   edits the file, including your own later fixes.

**The verification that matters:** the suite runs against the WORKING TREE (mine + theirs), so a
partial-stage commit is unverified by construction. Extract the index into a scratch directory
with `git checkout-index -a -f --prefix=<tmp>/` — that is byte-for-byte the commit tree — then
import and actually run it there. On 2026-08-21 that pass was green (10 cases + loc_residue) and
turned "the hunks look independent" into a measurement.

Cheap pre-checks that caught nothing but would have: grep the *unstaged remainder* for your own
vocabulary (must be 0 hits), and grep the *staged* version of a shared file for THEIR symbols
(must be 0) — an orphan reference is the failure mode partial staging creates.

**Limit (2026-10-18, Faz B paralel partisi):** parça düzeyinde ayırma yalnız adımlar birbirinin SATIRINA dokunmadıysa
çalışır. Paralel adımlardan biri öbürünün yeni fonksiyonunu yeniden adlandırdı ya da aynı satırı değiştirdiyse ara ağaç
hiç var olmamıştır; parçayı seçmek onu kuramaz, ancak elle uydurulur ve koşulmamış olur. O durumda parti tek commit'tir
(mesajda adım başına paragraf); per-step commit isteniyorsa adımlar aynı dosyalarda seri koşulmalı.

=== strings-csv-surgery
---
name: strings-csv-surgery
description: "strings.csv has no single quoting convention, so edit it by byte-span splice, never by rewrite; plus the token rules the integrity gate enforces"
metadata: 
  node_type: memory
  type: reference
  originSessionId: 954101b2-26e4-4348-828b-cca7aeee9b88
  modified: 2026-08-23T18:00:59.101Z
---

`localization/strings.csv` (1800+ keys, TR canonical) **cannot be safely round-tripped by a CSV
writer.** Its quoting is inconsistent row to row: some rows quote a field that needs no quoting,
some do not quote a sibling that does. A `csv.reader` → `csv.writer` pass with any single
quoting policy rewrites ~126 unrelated physical lines while claiming to change one key.

**Edit it by splicing byte spans.** Parse records with a quote-aware scanner that records each
record's `(start, end, key)`, then replace only the spans you mean to touch and leave every other
byte alone. Apply edits back-to-front so earlier offsets stay valid; an insert-after-anchor at
`end` and a replace of `(start, end)` compose correctly in that order. Verify by re-parsing and
diffing the key→value map: everything you did not name must come back byte-identical.

Format facts: header `keys,tr,en`, exactly 3 columns, UTF-8 **no BOM**, **LF only**, embedded
newlines are literal LF inside a quoted field (24 rows have them), trailing newline present.

**Those 24 embedded-newline rows are also a DELETION trap, measured 2026-08-23.** A sweep that
splits the raw text on newlines and drops lines whose first field matches a prefix removes only
the FIRST physical line of a multi-line record and leaves its continuation lines behind as
orphans. The
parse then breaks from that row onward and the key count collapses silently — 1929 → 939 in the
instance that caught it, while the file lost only 55 lines and `wc -l` looked fine. `loc_residue`
is what screams (`fakekey=17`); `loc_csv_integrity` also fails but *after* the damage. Delete
whole RECORDS with a quote-aware parse, never physical lines — this is the same reason the
memory above says splice spans rather than rewrite.

**What `loc_csv_integrity` enforces** (a smoke case in `endgame_smoke.gd`, not a standalone
script) — the two that bite:

- Placeholder tokens must match `[a-z_]+` and the **TR and EN token sets must be identical**.
  A Turkish-named token like `{yatırımcı}` is not recognised as a token at all, so it trips the
  stray-brace count and would render on screen as literal `{yatırımcı}`. Authors write Turkish
  placeholder names; the build needs the ASCII one in both columns. See
  [[frank-v6-landing-pass]].
- Every key must resolve in both locales (`translate(k) != k`), no duplicates, no positional
  `%s`/`%d`.
- **Exactly 3 columns** — tightened 2026-08-21 after it shipped a bug. A TR value carrying an
  UNQUOTED COMMA splits into four fields: TR keeps only the fragment before the comma, the EN
  column receives TR's *second* fragment, and the real EN falls into a fourth column nobody
  reads. Both columns are non-empty and token-free, so every other assertion passes and an
  English player sees a Turkish sentence on screen. The gate said `row.size() < 3`; it now says
  `!= 3`. **When you author a value containing a comma, quote it** — nothing else will tell you.

The companion gate is `scripts/debug/loc_residue.gd`, run as
`godot --headless --path . -s res://scripts/debug/loc_residue.gd` (exit 0 = clean, prints the
key count). Both are named in CLAUDE.md as "proof is a command, not a claim".

**Windows/Python gotcha:** stdout defaults to cp1254 and will die on `→` or `·`. Set
`PYTHONIOENCODING=utf-8`, and write results to a file with an explicit `encoding="utf-8"`
rather than printing them. MSYS-style `/c/...` paths do not work in Windows Python — pass
`C:/...`.

**1. Kaynak PNG'yi üzerine yazmak yetmez — Godot bayat `.ctex`'i servis etmeye devam eder.** Sekiz yeni 3840×2160 katman kurdum, sabitleri yeni ölçümlere göre güncelledim ve dokuz shot aldım: telefon kadrajda YOKTU. **2. Ama `--import` de bir sonraki koşuyu bozuyor.** `global_script_class_cache.cfg`'yi EKSİK yazıyor (77 sınıf yerine 76; alfabetik ilk giren `AngelRoundSystem` düşmüş). **Why:** İkisi de sessiz. Birincisinde screenshot'lar ÜRETİLİYOR ve düzgün görünüyor — yalnız yanlış sanatla, yani contact sheet'i yönetmene yollarsan onaylanan şey ölçtüğün şey olmuyor. İkincisinde gate'li bataryanın hata sayacı ateşleniyor ve gerçek bir regresyon sanıyorsun; daha kötüsü, o pencerede üretilen kareler autoload'ları ÖLÜ hâlde render edilmiş oluyor (bu turda yedi kareyi yeniden çekmek gerekti).

**How to apply:**
- Sanat kurduktan sonraki sıra kesin: **`--import` → bir tek ATILACAK ısınma koşusu → ancak sonra gate'li shot/smoke bataryası.**
- Bataryayı koşmadan önce doğrula: `stat -c%y` ile kaynak vs `.ctex`, ve `grep -c '"class": &' .godot/global_script_class_cache.cfg` sayısını projedeki `grep -rhoE '^class_name' scripts/ | wc -l` ile karşılaştır. Eşit değilse önbellek yarım.
- `Identifier "X" not declared` + `Failed to instantiate an autoload` ikilisini gördüğünde **önce önbelleği şüphelen, kendi diff'ini değil** — özellikle X senin dokunduğun hiçbir şeyle ilgili değilse. Aynı imza paralel oturum `class_name` eklediğinde de çıkıyor ([[concurrent-session-hazard]]).
